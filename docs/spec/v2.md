# todo.py v2 – priorities, due dates, labels, search, export

Status: draft. Owner: @agu5a. Cards link to one numbered section, not to the whole document.

## 1. Goal and scope

Turn the todo CLI from a flat checklist into something a small team can triage: every todo gets a priority,
an optional due date and labels; `list` can filter, search and sort; `export` hands the data to other tools.

Constraints that hold for every section:

- Standard library only, one file (`todo.py`), one test file per command (`tests/test_<command>.py`).
- Existing commands keep their current output and exit codes unless a section here changes them.
- Every new behaviour gets pytest tests; existing tests stay. A test that asserts v1 output may be updated only
  where this spec changes that output, and the card must name it.
- Dates are calendar dates (`YYYY-MM-DD`), no times, no time zones.

## 2. Storage schema v2

### 2.1 File format

The store becomes a JSON object with a version and the list of todos:

```json
{
  "version": 2,
  "todos": [
    {"id": 1, "title": "Pay rent", "done": false, "priority": "high", "due": "2026-12-01", "labels": ["home"]}
  ]
}
```

| Field | Type | Default | Rule |
| --- | --- | --- | --- |
| `id` | int | – | unique, never reused within one file (`max + 1`, as today) |
| `title` | str | – | non-empty |
| `done` | bool | `false` | |
| `priority` | str | `"normal"` | one of `low`, `normal`, `high` |
| `due` | str or null | `null` | `YYYY-MM-DD`, a valid calendar date |
| `labels` | list of str | `[]` | lowercase, unique, sorted; each matches `[a-z0-9-]{1,20}` |

### 2.2 Reading and migration

- A v1 store (a JSON list) is read as v2: every item gets the defaults above for missing fields.
- Every save writes the v2 format with all six fields present, so a v1 file becomes v2 on its first write.
- Commands that only read (`list`, `export`) never write the file, so they never migrate it.
- An object with any other `version` value fails every command: stderr `Unsupported store version: <v>`, exit 1,
  the file is untouched.
- A missing file still means an empty store, as today (`clear` keeps its own missing-file error).

### 2.3 Code

- One loader and one saver handle the format; commands never see the wrapper object, only the list of todos.
- One helper normalises an item to the v2 field set; commands that create or change items go through it.
- `AGENTS.md` "Data schema" is updated in the same change.

## 3. Priority

- `add <title> --priority low|normal|high` (default `normal`).
- New command `priority <id> <level>` sets it; unknown id: stderr `Unknown id: <id>`, exit 1.
- An invalid level is a usage error (argparse `choices`), exit 2, store untouched.
- `list` appends ` (high)` or ` (low)` after the title; `normal` adds nothing.

## 4. Due date

- `add <title> --due YYYY-MM-DD`.
- New command `due <id> <YYYY-MM-DD|none>` sets or clears it (`none` writes `null`); unknown id as in §3.
- An invalid date (`2026-02-30`, `tomorrow`) is a usage error, exit 2, store untouched. Parse with
  `datetime.date.fromisoformat` inside an argparse `type=` function.
- `list` appends ` due:YYYY-MM-DD` when set, after the priority suffix.
- "Today" comes from the `TODO_TODAY` environment variable when it is set (tests use it), otherwise
  `datetime.date.today()`. One helper returns it.

## 5. Labels

- `add <title> --label <name>`, repeatable.
- New command `label <id> add <name>` and `label <id> rm <name>`. Adding an existing label or removing a missing one
  is not an error (exit 0, store unchanged). Unknown id as in §3.
- Names are lowercased before validation; an invalid name (`a b`, 21+ chars, empty) is a usage error, exit 2.
- `list` appends ` #<name>` for each label, in stored (sorted) order, after the due suffix.

Full `list` line after §3–§5: `3 [ ] Pay rent (high) due:2026-12-01 #home #money`.

## 6. Filtering and search in `list`

All filters combine with AND. Without any filter `list` behaves as in §3–§5.

- `--open` / `--done`: only open / only done items; both together is a usage error, exit 2.
- `--priority <level>`: only that priority (repeatable: any of the given levels).
- `--label <name>`: only items carrying the label (repeatable: all given labels).
- `--search <text>`: case-insensitive substring match on the title.
- `--overdue`: open items with `due` before today (§4). Items without `due` never match.
- When nothing matches, stdout is `No todos` and exit 0, as for an empty store.

## 7. Sorting in `list`

- `--sort id|priority|due`, default `id` (today's order, insertion order equals id order).
- `priority`: high, normal, low; ties by id.
- `due`: earliest first, items without `due` last; ties by id.
- Sorting applies after filtering (§6).

## 8. Export

New command `export --format json|csv|md` (default `json`) writes to stdout, never to a file, exit 0.
It takes the same filters as `list` (§6) and the same `--sort` (§7).

- `json`: the list of todos (not the wrapper object), every item with all six fields, `indent=2`.
- `csv`: header `id,title,done,priority,due,labels`; `done` as `true`/`false`; empty `due` as an empty field;
  labels joined with `;`. Use the `csv` module (quoting of commas and quotes in titles).
- `md`: one line per item, `- [x] <title>` or `- [ ] <title>`, followed by the same suffixes as `list`.
- An empty result: `json` prints `[]`, `csv` prints only the header, `md` prints nothing.

## 9. Errors and exit codes

| Situation | stderr | exit |
| --- | --- | --- |
| Success | – | 0 |
| Unknown id | `Unknown id: <id>` | 1 |
| Unsupported store version | `Unsupported store version: <v>` | 1 |
| `clear` without a store file | `No todos file: <path>` | 1 |
| Invalid argument (level, date, label, flag combination) | argparse usage message | 2 |

On any non-zero exit the store file is unchanged.

## 10. Delivery order

§2 comes first: every other section reads or writes the new fields. After it §3, §4 and §5 are independent of
each other. §6 needs §3–§5 (it filters on their fields), §7 needs §3 and §4, §8 needs §6 and §7.

## 11. Out of scope

Recurring todos, reminders, times and time zones, multiple stores or users, import, colour output,
a config file, any third-party package.
